# GateGuard · 守门

面向电力边缘服务的 **Linux 文件权限策略生成、访问控制与可验证恢复工具**，定位于 2026 操作系统设计赛华东区域赛 **操作系统应用开发赛道—系统工具方向**。

## 解决的问题与技术主线

1. 服务文件权限配置粗放，人工细化和维护困难：用明确业务职责与正常访问证据辅助生成规则并解释来源。
2. 收紧后是否影响业务、目录放权扩大多少权限缺少依据：独立验证正常任务、违规操作及授权范围。
3. 权限内数据损坏后恢复结果与合法损失难核验：停服恢复、重建保护并检查文件、业务与损失。

进程/文件访问采集 → 规则生成/解释/编译 → BPF LSM 内核检查 → cgroup 进程控制 → Btrfs 恢复与验证。电力数据驱动采集/报表/维护负载，不能从电压值判断越权。数据库记录级、应用用户级和遥控命令授权不纳入本版。

特色与拟贡献是职责约束下的可解释规则归纳、编译执行一致性和可核验恢复；以人工、精确、简单目录、自研四种配置及消融验证，成熟机制本身不当作原创。算法搜索、评分和参数 **待后续 B 算法讨论**。

当前仓库是设计与任务约定，尚非已完成软件；文档/契约版本 **3.1，2026-11-24**，真实 Linux 能力与结果必须实测。

## 工作链路与开工顺序

业务授权规格与主体/资源登记 → 标准电力输入 → Linux 业务和真实访问 → 原始包校验 → F 派生视图/划分 → Windows 离线学习 → profile 回传 Linux → 当前能力/绑定编译 → 内核及正常业务验证 → 独立损坏恢复与评测。

G0 并行准备环境、模型/fixture、业务骨架和规格首版；G1 小批完整真实包准入后再扩大；G2 学习/执行一致与正常业务；G3 独立恢复；G4 冻结对照、复现和交付。先读 00/08/11/12/09，再读自己的角色。Windows/Linux 环境分开，软件不写死成员本地路径。
