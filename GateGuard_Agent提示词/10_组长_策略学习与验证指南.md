# 组长的权限策略研究、学习与验证指南

文档版本 3.1，2026-11-24。GateGuard 是操作系统应用开发中的 Linux 系统工具。B 负责研究设计、方法实现和实验方案；组长组织运行、审定参数/发布及最终结论，两种职责可由同一人承担。算法搜索、评分、权重与阈值留待后续讨论。

## 开始前接收什么

- 按 11 审定的主体/资源目录、BusinessSpec 和学习可见粗粒度约束，明确来源与模拟约定。
- B 的 schema 3.1、Policy.learn/explain/validate_replay、LearnConfig、fixture 与已实现功能。
- F 按 12 交的完整数据包、原始载荷/hash、规范化来源、learning-view/evaluation-view、划分与质量/排除报告。
- A 的真实能力/ABI/限制，C 的正常业务、安装、恢复入口和可信身份映射。

正常成功访问不自动证明授权，训练未见不自动证明违规；电力数值不提供权限边界。完整评测预期不能当自动方法的答案输入。

## 怎样研究和运行

1. G0 确认业务范围与规格首版；环境、模型和 fixture 并行。讨论 B 方法前先明确约束输入、候选空间、对照与可验证指标，不提前预设最好结果。
2. 选择 Windows Python 3.12 独立环境，校验小批真实包与 learning-view。学习仅取准入 normal train，正常 validation 用于覆盖和选参，不混作训练。
3. 比较 manual、exact、grouped 的简单目录配置与自研配置，共四种实验配置，保存全部开关、代码/输入 hash 与种子。人工基线的知识输入单独披露，不能用最终 test 反推它。
4. 检查规则范围、来源、低频需求和编译语义；已知硬约束符合性与可选择范围的授权代价分开。离线回放不代表 Linux 业务已通过。
5. 高层 profile 回传 Linux，由 A/B 按当前 Capabilities/Bindings 编译、审核安装，C 运行真实正常业务。失效/不支持不静默放宽；失败保留证据并回退有效版本或停服。
6. 冻结方法、参数与测试清单后，才组织最终独立 normal/violation/boundary/recovery。F 的 evaluation-view 用于评测，development 反例不计入冻结 test；不得据 test 结果继续调参后仍报独立测试。
7. 分别汇总任务完成、误拒、实际阻断、有限清单额外授权、规则与解释、开销和恢复损失；未来对象范围、未知/前置失败/不支持/未测可见。解释效率需人工实验，不能由界面或规则数推断。
8. 写清相比各基线改善什么、付出什么；无改进如实缩小贡献。权限内错误内容用独立恢复验证，不称为权限自动检出。

## 待实现的命令示例

以下由 B/C 按 08 实现后才可使用。dataset 目录携带 learning-view，B 在 learn 内验证其 view_kind 和允许 split；CLI 门面仍归 C，不另建第二套入口。

```text
python -m gateguard.cli dataset validate --dataset data/processed/power-v1
python -m gateguard.cli policy learn --dataset data/processed/power-v1 --config experiments/grouped.json --out artifacts/policies/exp-001
python -m gateguard.cli policy explain --profile artifacts/policies/exp-001/profile.json --rule rule-001
python -m gateguard.cli policy validate --profile artifacts/policies/exp-001/profile.json --dataset data/processed/power-v1 --split validation
```

缺正常覆盖交 D/C；字段/约束/归纳问题交 B；真实内核差异交 A/B；恢复/健康问题交 C；F 保留原始事实并出补采清单。不能通过修改真值或过滤坏结果让学习通过。
