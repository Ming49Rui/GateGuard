# 组长的权限策略学习与验证指南

本项目是服务安全系统，当前学习模块是规则归纳和权限收紧，尚未指定神经网络。你负责组织实验、运行 B 提供的程序、选择参数、审核策略和解释结论；ABC 负责实现系统与工具，DEF 负责数据准备、采集、质检与划分。

## 你接收什么

- B：可在 Windows Python 3.12 运行的 Policy.learn/explain/validate_replay、LearnConfig、示例命令和算法说明。
- F：已质检数据包、train/validation/test 划分、来源/hash、质量报告；D/E 的场景真值可追溯。
- A：Ubuntu 后端能力与限制；C：Linux 正常业务验证、安装、事故和恢复入口。

## 你怎样操作

1. 在 Windows VS Code 选项目解释器，确认数据包校验通过；先用少量真实 normal run 跑通学习。
2. 比较人工职责、精确汇总和业务分区归纳三组策略。调参只使用训练与验证数据，保留每次 config、代码版本和输出。
3. 检查每条规则来源和归纳范围；回放通过只说明观察数据上没有冲突，还要让 ABC 在 Linux 上跑正常业务。
4. 把高层 profile 传回 VM；由 A/B 用当下能力与资源绑定编译安装，C 完成正常业务验证。受保护资源或主体改变要重新绑定，不能拿 Windows 目录或旧 inode 直接执行。
5. 冻结最终方法和测试清单后，组织 DEF 用统一工具采集最终测试。记录阻断、误拒、额外授权、性能与恢复损失，保留没防住或未测试项。
6. 形成答辩结论：相比人工配置/精确汇总改善了什么，代价是什么；没有改善就如实调整结论，不补造数字。

训练数据不是直接输入一列电压值，而是模拟业务运行后的文件操作记录。电力原始数据用于驱动业务；实际主机事件用于权限学习；违规/边界/恢复场景用于独立评测。

## 待实现的命令例子

以下命令由 B/C 按 08 契约实现后使用，目前不应被当作现有程序：

```text
python -m gateguard.cli dataset validate --dataset data/processed/power-v1
python -m gateguard.cli policy learn --dataset data/processed/power-v1 --config experiments/grouped.json --out artifacts/policies/exp-001
python -m gateguard.cli policy explain --profile artifacts/policies/exp-001/profile.json --rule rule-001
python -m gateguard.cli policy validate --profile artifacts/policies/exp-001/profile.json --dataset data/processed/power-v1 --split validation
```

收到数据后发现必要业务没覆盖，给 D 明确补采任务；发现字段/归纳问题交 B；真实内核结果不同交 A/B；恢复或业务问题交 C。F 保留原始数据与划分，不能直接改坏样本让训练通过。
