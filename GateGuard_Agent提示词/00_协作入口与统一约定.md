# GateGuard v3.1 任务分发入口

文档与契约版本 3.1，2026-11-24。本目录是直接分发的 Markdown 提示词集，07—12 是公共部分。各角色拿到整个目录即可启动；项目介绍书是扩展背景，不作为启动依赖。当前内容为待实现约定，不是软件与实测成果。

## 项目主要解决什么

定位：面向电力边缘服务的 Linux 文件权限策略生成、访问控制与可验证恢复工具，参加操作系统应用开发赛道的系统工具方向。

- 服务文件权限粗放，细化维护困难：基于业务职责和正常访问证据生成候选规则，解释依据。
- 收紧与放宽代价不清楚：比较正常任务可用性、额外授权和规则复杂度，验证内核实际执行。
- 权限内损坏后的恢复效果难核验：停服、恢复、保护重建、文件与业务检查，报告合法损失。

系统技术主线是进程/文件操作、访问控制与 LSM、cgroup、文件系统恢复。电力负载体现采集/报表/维护职责及生命周期；不做电压预测、电网故障诊断、遥控命令授权和数据库记录级鉴权。成熟机制本身不算原创，改进以对照实验为准。详见 11。

## 谁做什么

| 人员 | 负责 | 交接边界 |
|---|---|---|
| A | 采集、BPF LSM、能力探测、cgroup 原语 | 与 B 冻结执行语义，与 C 核对可信身份，不重写算法/恢复编排 |
| B | 研究设计、策略工具、共享契约、编译、存储 | 汇总规格与候选方法；组长审定参数/发布与最终结论 |
| C | 模拟网关、主体资源登记、CLI/部署、恢复、面板、集成 | 调用 A/B，明确进程/cgroup 与文件布局 |
| D | 输入来源、标准化电力记录、正常场景与采集 | 不编写网关主体，按 12 交完整 raw/normal |
| E | 违规/边界/损坏场景、独立预期与采集 | 不自建采集器/特权入口，按 12 留前置与损坏证据 |
| F | 质检、规范化派生、分组划分、封包和统计 | raw 字节不变，不替 B 设计算法，不替组长选最终参数 |
| 组长 | 组织实验、审定规格/方法/参数、审核发布和最终分析 | 是 A/B/C 之一，可同时承担 B；不得用冻结 test 调参 |

A/B/C 是三名参赛成员；D/E/F 是三个辅助数据任务，不增加参赛成员。来源与实际贡献按事实记录并按当届要求披露。

## 阅读与启动顺序

1. 所有人读 00、08 契约、11 业务/权限、12 数据交接、09 环境，再读自己的 01—06 和 07 对应条目。
2. G0 并行做 A 环境/B 模型/C 工程与可信身份骨架，D/E 场景、F 质检 fixture；同时确认首版主体/资源目录、BusinessSpec 与粗粒度 LearningConstraints。
3. 规格确认后用统一入口采 G1 小批真实包，F 检查、组长/B 准入后再扩大。raw/派生、预期/事实/裁决分别保存。
4. G2 Windows 离线学习，profile 回传 Linux 按当前能力/绑定编译安装，A/B 验证执行、C 验证正常业务。
5. G3 独立制造并确认合成损坏后恢复；G4 冻结对照/测试、复现与交付，openEuler 单列兼容。

G0 不是要求所有人互相等待。算法搜索/评分/权重/阈值留待 B 讨论，不影响先做环境、规格和共享模型。每人 handoff 区分 implemented/tested/not_run/unsupported。

## 文件所有权和变更规则

核心缩写路径均相对 src/gateguard/：B 管 contracts/policy/store/guard/decision.py、schemas 与共享接口文档；A 管 collector、其余 guard、preflight/cgroup；C 管 response/web/cli.py/__main__.py。bpf、examples、scripts、data、schemas、docs、deploy 均相对仓库根。

C 管 examples/power_gateway、根依赖/包装入口、部署和工程文档；D/E 管各自输入/场景/raw；F 管 processed/splits 和 data/eval 质检、规范化、统计工具。B 定义 Normalize/规格模型语义，F 实现派生管道，不能各复制一份。

业务规格由 B 汇总，C 核对进程与文件实现，D/E 提供需求/反例，F 核对可评测性，组长批准。后续跨所有权修改先写 docs/notes/<角色>-proposal.md；契约变更由 B 汇总影响交组长审定，根依赖交 C。共享工作树不擅自切分支、覆盖、提交或推送。交接 docs/handoffs/<角色>.md。

## 价值与验收

人工职责、精确汇总、简单目录归纳、自研归纳收紧四种配置对照，披露知识输入与代价。解释有来源/正确性检查；性能、实际阻断和恢复都用 Linux 真实证据。评分和候选搜索待算法讨论，不能预设优于基线或全局最小权限。

固定普通目标与合成沙箱，后端语义无法表达要报错。权限内内容错误单列恢复，不虚报检出。root/内核失陷不在范围。采集丢失、未解析、unknown、前置失败、未支持与未测均保留。

## 课程与竞赛共同交付

- 操作系统应用开发—系统工具方向；2026 技术方案第 2 页为范围、第 3 页为评分、第 4 页为交付。按官网具体题目框架确认选题，2025 解读/国赛作品仅作背景与深度参考，不要求本系统工具实现完整内核。
- C 汇总完整源码、构建环境、设计、功能/性能与同类比较、过程历史和 README 演示视频；按赛事 GitLab 托管要求提交，GitHub 开发仓库不能替代。
- 代码满足实际适用许可，文档按赛事采用 CC-BY-SA 4.0。按章程如实披露 AI 工具/模型/使用场景和成果、交互记录，在开发记录、设计与答辩材料中说明。
- 课程约 15 分钟展示由一人组织，解释系统调用、内核裁决、身份/进程控制和文件系统恢复，并用实验记录支撑。功能/平台未测分开，预留备用录屏。
- 演示链路：正常业务生成规则及来源 → 相同普通服务职责外操作被实际拒绝 → 独立权限内损坏后的停服恢复与合法损失核验。
