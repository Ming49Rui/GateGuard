# GateGuard v3 任务分发入口

本目录是可直接分发的 Markdown 提示词集，用于组员和各自 agent 开工。请将整个目录放进各自代码工作副本，07—10 是协作提示词的一部分。各角色所需项目背景、职责、接口和验收均在本目录。本文档集描述待实现系统，命令与接口需按角色任务实现和验证。

参赛团队为 A/B/C 三人，组长是其中一人。D/E/F 是辅助数据任务编号，不列为参赛成员；辅助来源和实际贡献如实记录。六个编号表示任务分区。

## 谁做什么

| 人员 | 负责 | 不交叉承担的内容 |
|---|---|---|
| A | 采集、BPF LSM、能力探测、cgroup 原语 | 不重写策略算法或恢复编排 |
| B | 契约、策略学习工具、编译、存储 | 实际训练/调参和最终选择由组长负责 |
| C | 模拟网关、CLI/部署、恢复、面板、集成 | 调用 A/B，不复制核心机制 |
| D | 电力输入、正常场景准备与采集 | 不承担模拟网关主体开发 |
| E | 违规/边界/损坏场景与采集 | 不自行实现内核防护和快照切换 |
| F | 数据质检、划分、整理和统计工具 | raw 只读，最终实验解释由组长负责 |
| 组长 | 运行权限策略学习、调参、审核和实验分析 | 通过稳定工具接手，不从零补训练程序 |

## 阅读与启动顺序

1. 所有人读本文、08 契约和 09 环境；再读自己的 01—06 文件。介绍书是可选扩展背景。
2. 07 开源清单按角色阅读，来源快照与文件许可已核查，代码尚未在目标 VM 实跑。
3. ABC 在 G0 并行：A 验证 Ubuntu 内核环境，B 发布共享模型/fixture，C 建工程和网关。DEF 同时准备输入、场景与质检工具。
4. G1 小批真实 run 包先交 F、组长/B 检查；通过再批量采集。
5. G2 组长 Windows 学习，profile 回传 Ubuntu，A/B 编译安装，C 验证正常业务。G3 独立损坏恢复。G4 冻结测试并整理交付，openEuler 单独兼容验收。

顺序是接口依赖，不是等待所有前置模块全部开发完。每人维护自己的 handoff，清楚区分 implemented/tested/not_run/unsupported；不能把设计目标写成成果。

## 文件所有权和变更规则

B：contracts/policy/store/guard/decision.py、Schema 与接口实现文档；A：collector/BPF/其余 guard；C：examples/power_gateway、response/web/cli、根依赖、README/design/threat-model/provenance；D/E：各自输入、场景与 raw；F：processed/splits、质检与统计。

核心 Python 模块的缩写路径均相对 `src/gateguard/`（如 contracts/、collector/、guard/、response/、web/、cli.py），BPF C 源码位于仓库根 bpf/；examples/、scripts/、data/、schemas/、docs/、deploy/ 均相对仓库根。A 的能力探测实现放 src/gateguard/preflight.py，C 的 CLI 调用它。C 负责创建包装入口、可编辑安装与依赖清单，B 发布共享模型后各方导入，不另建同名顶层包。

相邻模块修改交所有者，写 docs/notes/<角色>-proposal.md；接口变化由 B 汇总并经组长确认升级版本。每人交付 docs/handoffs/<角色>.md。共享工作树不自行切分支、覆盖、提交或推送；版本控制的具体操作按团队安排执行。

## 本项目的价值和评估

帮助运维理解与收紧服务权限，限制越权影响，并证明恢复结果和合法损失。用人工职责与精确汇总作基线，不以接入电力 CSV 或出现 BPF 名称证明创新。已有 systemd/LSM/快照工具具有相近基础能力，本项目要展示配置解释、业务验证和恢复证据带来的可量化收益。

电力输入驱动模拟业务；真实系统行为用于策略学习；异常和恢复数据独立评测。策略学习是规则归纳，不预设深度学习。权限内错误内容、root/内核失陷等边界必须清楚。课程约 15 分钟展示与竞赛工程、文档、过程、公开托管和 README 视频链接一并准备。

## 课程与竞赛共同交付

- 课程按实践项目准备 PPT 并由一人约 15 分钟展示，解释权限/系统调用、内核裁决、进程隔离和文件系统恢复，包含团队实际探究及实验结果。人数按团队既定安排。
- 参赛定位为 2026 华东区域赛操作系统应用开发中的系统工具。C 汇总完整源码、构建环境与复现入口；ABC 提交设计、功能/性能与同类方案比较；DEF 提供可追溯数据与教学实验材料；组长审核最终分析。
- 保留真实 Git 历史、过程记录、视频与 README 链接，按当届要求在指定平台公开代码和文档；源码按实际复用文件满足适用许可证，文档按赛事技术方案采用 CC-BY-SA 4.0。
- 平台以 Ubuntu 开发，openEuler 后续单独兼容验证；平台兼容不替代算法及系统实验。对比和消融报告必须区分待测、失败、不支持和已实测。
- C 编排最终演示：正常业务产生规则和来源 → 普通服务越权被实际拒绝 → 另一次权限内损坏触发恢复并报告合法损失。用真实日志支撑展示，准备备用录屏。

课程依据为授课“探究与实践要求”图片；赛事依据为[官网](https://os.educg.net/#/index?TYPE=26OS_HDF)和[2026 华东区域赛技术方案](https://gitlab.eduxiji.net/csc1/csc-os/os2026-regional/os2026-east-china-region/-/blob/main/2026年操作系统设计赛华东区域赛技术方案-1010.pdf)。后续通知由组长核对再同步，不以提示词取代官方规则。
